# 宿傩桌宠 0.4.7 发布与验收范围

0.4.7 修复 AI 对话窗口再次打开无响应：菜单仍在跟踪时等待其关闭，再创建或呈现聊天；若 Qt 显示状态与 Windows 实际可见性不一致，重新呈现同一窗口。用户在最终安装版确认首次打开及关闭重开“两次都正常”。运行代码与本机已验收安装包一致，发布时保持 Setup.exe 的字节不变；发布补验见 [#66](verification/issue-66/README.md)。

发布补验：完整回归 396 项通过，类型检查 27 个文件通过。最终冻结程序和实际安装目录的完整隔离自检均通过，已补齐初次交付时因审批超时未完成的验证；235 个安装文件匹配构建报告。安装包内的验收说明来自原本机候选构建，本次发布页、源码文档及补验附件提供完整 0.4.7 记录。

本版本包含以下 0.4.3–0.4.6 本地候选的功能和修复；此前正式发布为 0.4.2。

0.4.6 修复音乐跳动复用旧音频输出导致耳机切换无效的问题。每轮播放重新选择当前默认输出，播放途中监听设备变化，按已处理采样位置接续并保留原始 15 秒截止时间；所有输出断开时停止，重新连接后可手动重播。

设备切换专项 6 项通过，连同音乐、模式和设置相关回归共 37 项通过。两项设置测试需访问本机 HTTP 服务，在允许回环网络的环境补测通过。mypy 26 个源文件通过。使用真实 OPPO Enco Free4 和 Realtek 输出，通过合成默认设备变化通知核验真实 QAudioSink 的两次切换、音频时钟连续与按期停止；未改动 Windows 默认输出设置，尚不代表物理插拔或人工听感验收。冻结与安装版完整播放结果见本次交付记录。

0.4.5 将“桌宠设置”设为与 AI 对话相同的普通窗口类型，用户在本机实际点击后已确认设置界面出现。0.4.4 虽通过隔离检查，但用户仍无法看到设置；Qt 内部 visible/active 标记不足以判定实际展示。临时点击诊断已从最终版本移除。

保留 0.4.4 的菜单时序调整：右键和托盘的“桌宠设置”延迟到菜单退出后创建并激活窗口。`SukunaPet.exe --verify-settings <不存在的新目录>` 使用隔离偏好，通过真实鼠标菜单选择验证设置为普通窗口、可见、获得焦点且不在菜单循环内创建。源码回归另覆盖托盘入口和关闭后窗口复用。

2026-10-28（Asia/Shanghai）。本地候选新增“音乐跳动”，位于“任务联动”下方：使用用户指定视频的 0–14 秒音频，随约 128 BPM 的节拍循环跳动，总计约 15 秒后停止并保持静止，等待再次点击。音频由直接 PCM 输出播放，动作使用已处理的音频采样时间；切换其他模式或退出时立即停音。重启记住音乐模式但不自行播放。此候选未公开发布。

音乐专项测试覆盖片段长度、音频时钟与循环、停止后保持静止、手动重播、拖动不播放、缺少音频失败收口以及菜单切换/退出停音。完整 Windows 播放核验入口为 `SukunaPet.exe --verify-music <不存在的新目录>`，会实际播放约 15 秒，并使用隔离偏好记录菜单、循环、截止、静止、重播与停音结果；不会访问真实聊天、密钥或宿主配置。具体核验结果另见本次交付记录。

## 保留的 0.4.2 功能与验证范围

2026-10-27（Asia/Shanghai）。本版修复 #62：桌宠右键和托盘菜单在原生菜单事件分发返回后再打开并激活 AI 对话窗口。新增真实菜单回归，覆盖首次打开、关闭重开、最小化恢复和窗口复用；冻结安装自检也覆盖实际右键入口。验证记录见源码包 `docs/verification/issue-62`。自动化结果不代替用户现场复点确认。

保留 0.4.1 的 #61 修复：桌面启动时自动发现 DeepSeek 自带运行时中的 pnpm/Node，支持入口目录提示和失效提示回退。保留已安装版中的系统托盘与自适应透明圆角气泡。提示词版本 `sukuna-2026-10-27-v1`；固定 `deepseek-flash`、关闭思考。版本与冻结模块逐文件摘要见 build-report.json；Setup、源码 ZIP 与报告的哈希见 SHA256SUMS.txt。

0.4.0 的作者真实试聊已在 #53 确认通过；本版未修改人设或对话请求逻辑。#61 修复后已在本机安装并恢复实际 desktop profile 插件，用户正常重开 DeepSeek 后确认任务跳动恢复。安装与配置操作仍会先备份，启用接入和选择任务联动分别保存。

源码行为和原生视觉的既有证据见源码包 `docs/verification/issue-49` 至 `issue-55`；接入修复验证见 `docs/verification/issue-61`。只按记录的实际结果判定，不把本机安装、隔离数据或合成请求当作干净 Windows 或真实计费服务验证。

安装验证入口为 `SukunaPet.exe --verify-installation <不存在的新目录>`，在真实冻结运行时验证独立测试目标的 Windows 凭据读写/删除、跨进程读取、真实适配器拒绝过长值后的仅内存降级、合成会话与人设重启恢复、窗口复用/关闭、兼容旧偏好及未知字段、Windows TLS CA 可用性。入口不会访问产品凭据目标、个人聊天或宿主 profile，也不会调用计费接口。`result.json` 记录结果，失败时非零退出并记录异常类型。它不验证服务商真实回复或所有安全存储策略故障。

当前单显示器 Windows 11 x64；真实多屏、负坐标屏、混合 DPI 切屏、硬件插拔及无 Python 的干净 Windows 仍未实测。既有任务桥的日常范围及未知归属限制沿用 #41/#42，未扩展支持矩阵。Node/pnpm 是接入维护的外部前置，不是角色或聊天的运行依赖。

程序不含开发 Key、个人会话、参考程序资料或原视频。会话与偏好保存在自己的用户数据目录，Key 保存在当前用户 Windows 凭据管理器；卸载保留这些用户数据。Qt/Python 等第三方许可及 dsh-pet MIT 全文随包提供，含 Copyright (c) 2026 Merzlin。Setup 未签名。

0.3.0 的历史用户验收与硬件边界见源码包 `docs/verification/issue-42/README.md`；AI 功能另按 #53 的作者验收记录追溯。
