# #16 跨屏拖动时保持角色完整可见

日期：2026-10-24（Asia/Shanghai）。规格为 [#16](https://github.com/xyd-0811/skip-pet/issues/16) 和父规格 #12。用户确认审查基点为 `48479ab`，并确认新增 Qt 窗口公开鼠标输入与几何结果的测试边界。既有规划及词表改动保留，不纳入本次提交。

## 实现与回归

按鼠标全局逻辑坐标选择目标 `QScreen`，在每次拖动移动及释放时，用原生命中掩码的非透明包围范围约束到该屏幕的 `availableGeometry()`。透明留白可越界；不会把多个屏幕外包矩形中的空隙当成工作区。没有命中屏幕时选最近的独立屏幕。负原点保持原值，尺寸由 Qt 的逻辑坐标处理，不对全局原点再除一次 DPI。移动前选择目标屏幕，使 Qt 的绘制和原生命中区域跟随目标屏幕 DPI。

屏幕增减、几何/工作区变化和原生屏幕/DPI 通知后，在 Qt 完成平台更新时重查可见位置。播放与拖动的应用级判定沿用 #15；位置约束不调用点击入口，不修改素材尺寸或设置格式。

TDD 首项在修改前失败：拖到任务栏下方后角色出界。加入每次移动/释放约束后通过。第二项先验证工作区变化不会恢复可见位置，失败后再加入屏幕通知处理。共新增 11 项窗口行为测试，覆盖真实 Qt 窗口的工作区约束、通知恢复，以及系统边界夹具中的左侧负坐标、上方屏幕、逻辑坐标空隙、任务栏偏移、跨屏后再次点击、只有释放没有移动事件、透明留白允许出界。

多屏夹具中的逻辑尺寸分别代表 100%/150%/200% 布局，只检查逻辑几何算法；没有真实切换 DPI，不作为混合 DPI、跨屏命中或原生屏幕切换通过的证据。

Qt 依据：[高 DPI 与 Windows 屏幕坐标空隙](https://doc.qt.io/qtforpython-6/overviews/qtdoc-highdpi.html)、[各屏幕可用区域](https://doc.qt.io/qt-6/qscreen.html#availableGeometry-prop)、[选择窗口屏幕](https://doc.qt.io/qt-6/qwidget.html#setScreen)。Qt 6 默认启用 Windows Per-Monitor DPI Aware V2；本次沿用 Qt 原生缩放。

## 真实 Windows 记录

Windows x64、Python 3.14.4、PySide6/Qt 6.12.0，Qt 平台 `windows`。见 [screen-layout.json](screen-layout.json)：仅一块 G24H1，屏幕 `(0,0,1920,1080)`，可用区域 `(0,0,1920,1032)`，100% 缩放（DPR 1.0），底部任务栏 48 像素；角色逻辑范围 253×247。

启动 `python tools/verify_pointer_native.py --output docs/verification/issue-16`，生产 `PetWindow` 接受桌面系统鼠标输入；观察器只记录状态和几何，不注入鼠标、不读写用户模式设置。原始轨迹见 [native-trace.jsonl](native-trace.jsonl)。本次拖动及连续点击来自桌面人工输入；代理使用 `computer-use` 技能的 `@oai/sky` 完成可见角色右键及菜单退出。早先代理的拖动/单击尝试分别因截图标识和并发人工输入被拒绝，未作为已执行的验证步骤。

- 2661 次定时观察中，状态发生变化的 981 条记录被写入日志；所有记录均 `fully_visible=true`。
- 窗口到达左/上/右/下边界，记录中的 x 范围为 `0..1667`、y 范围为 `0..785`；含移动过程和释放后记录。最大可见右沿为 1919，下沿为 1031，避开任务栏。
- 最初 876 条记录（文件行 1–876）在四边之间拖动和释放，始终停留阶段 0，没有阶段推进。之后在右下边界点击可正常逐阶段播放；最后一次拖到 `(1645,785)` 后仍保持阶段 2。
- 可见脸部右键打开“点击跳动 / 持续跳动 / 退出”，当前勾选点击跳动，阶段仍为 2。系统鼠标选择退出后进程返回 0，标准错误为空。
- 普通应用前置时，日志仍记录 `native_topmost=true`。透明穿透的跨应用详细证据沿用 #15，本次没有重复将其作为完整复验。
