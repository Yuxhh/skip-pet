## 应用级行为

测试沿用父规格已确认的统一入口：`PetApplication` 接收点击、模式选择和可控时间，观察公开的 `view` / `mode`。设置保存/恢复由使用同一路径的新应用实例检验。没有通过 Qt 私有成员、绘制次数或内部播放变量断言行为。

- 首次无设置时采用点击模式，静止待机。
- 持续模式跨多个弹跳周期不停止；保留 3× 纯眼动、局部修正和 240ms 眨眼。连续运行、普通点击、闭合/睁眼中点击、跨周期睁眼中点击和快速连点共 6 组夹具直接执行原型 `next` / `tick` / `paintSprite` 生成。包括周期衔接前后相邻 1ms 的观察点。累计采样误差容许 0.5 源像素和 0.03 眼皮闭合程度，未复制移植实现的公式充当断言。
- 各普通阶段切回点击模式，从原位置完成当前阶段后保持，不补完整周期。闭合期间切换保留 120ms 换位和完整 240ms 眨眼；睁眼期间，按原型已经恢复的眼动完成所在阶段，并等眨眼结束后保持。
- 点击不改变持续模式；同一模式重复选择不延长当前阶段。视线 2 停留后进入持续模式，会先眨眼换位，避免在阶段边界漏掉眨眼。
- 大步长与 1ms 小步长在多轮播放及穿插点击后得到同样的可见状态，不用 UI 调用耗时证明动画时长。
- 模式在选择时保存，重新建立应用恢复持续/点击模式；只保存 `mode`。不存在或损坏/不支持的设置回退至点击模式。原子替换失败保留原模式，由原生窗口显示重试提示。

## 原生 Windows/Qt 菜单与重启

执行 `python tools/verify_modes_native.py`，三个独立进程均正常以返回码 0 结束。程序使用生产 `PetWindow`、生产播放入口、生产设置存储、实际 Windows 平台的真实 `QMenu` 和菜单动作；通过 Qt 自带输入工具点击菜单项。程序不读取或修改真实运行的模式设置，使用 `QStandardPaths` 测试配置目录，并在结束时还原其中已有设置。

1. `select-always`：无设置启动，菜单勾选点击跳动；点击持续跳动，读取保存结果仅含 `{"mode":"always"}`。点击角色后重新打开菜单，仍勾选持续跳动。点击退出，进程结束。
2. `restore-always`：重新启动，菜单勾选持续跳动；选择点击跳动，保存结果仅含 `{"mode":"click"}`。点击角色后仍勾选点击跳动，菜单退出结束进程。
3. `restore-click`：再次启动，菜单恢复点击跳动；点击角色及菜单退出正常。三个菜单都只包含点击跳动、持续跳动、分隔线和退出，模式项互斥。
