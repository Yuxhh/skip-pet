# #64：桌宠设置菜单激活修复

2026-10-28，Windows 11，0.4.5 本地候选，未公开发布。

用户报告点击“桌宠设置”无反应。源码和原安装版直接调用设置窗口均成功，未在隔离环境稳定重现完全不显示；原生菜单检查确认旧流程在 QMenu.exec 内创建并激活窗口。右键与托盘入口现使用零参数队列槽，在菜单退出后创建/激活窗口；槽会丢弃 QAction 的 checked 参数。参考本地 dsh-pet 的菜单关闭后执行窗口命令机制。

**上一轮结论已被现场反馈推翻。** 用户确认 0.4.4 设置依然不显示，但 AI 对话正常。检查只有一个当前安装版进程。临时诊断捕获用户实际点击：菜单触发，无创建异常，Qt 将 SettingsWindow 标记为 visible/active；用户屏幕上仍没有窗口。直接将这些标记当作显示成功，导致上一轮误判。

有效修复：SettingsWindow 的父窗口是透明置顶 Tool 类型桌宠，将设置从默认 QDialog 类型改成与正常 AI 对话相同的 Qt.Window 类型。普通窗口可被 Windows 窗口工具识别。安装 0.4.5 后，用户再次实际点击并明确回复“设置界面出现了”。最终版移除临时诊断入口与日志模块，诊断材料仅留在开发目录 .scratch/settings-open/，不随应用打包。

原生回归命令：`SukunaPet.exe --verify-settings <不存在的新目录>`。使用真实菜单鼠标选择、隔离设置和会话目录；凭据按正常启动加载，不修改个人聊天或密钥，也不发起 API 请求。旧流程记录 created_inside_popup=true，回归失败；时序调整后仍未解决现场显示问题，最终以普通窗口类型和用户确认判定。安装版结果及截图附于本目录。
