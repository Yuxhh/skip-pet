# #24 点击回弹与连点接续验证

日期：2026-10-25。正式源码窗口；保留 #23 的头眼推进及独立眨眼。当前安装器仍是 #17 首版，自动节奏、动态贴边、新安装器与硬件多屏由后续票处理；本票不修改或关闭父规格 #22。

## 实现与基准

每次统一 `click()` 同时推进头眼并重启回弹时钟。`view.bounce_scale` 只读提供整体宽高比例，220ms 恢复；`holding` 保持已有的头眼到位含义，因此头眼已停留时回弹仍可恢复。连点从当前头部连续进度替换目标，回弹归零，不叠加也不排队。冻结模型中的闭眼换位继续只作用于眼睛。

绘制在固定视口与显示缩放之内、所有角色层之外，围绕全 RGBA 素材底边中心 `(709.5,1108)` 施加同一变换。透明留白参与锚定，前后衣领和头颈共享变换；无需第二次缩放已经裁剪的画布。最终图像仍统一用于绘制和动态命中。手势沿用系统阈值与 Qt 原生自动捕获，无需改变已有输入语义。

`tools/capture_v5_traces.mjs` 直接执行动作冻结提交 `32c9f985d4467c1527b09c34f6868a3ccd3f85b4` 的 `Motion`、`Rig`、`Bounce` 和眼睛绘制，七组轨迹新增回弹输出。1ms 采样覆盖四次点击、普通动作/眨眼闭合/睁开中再点、快速五次、大量替换目标和第二次眨眼。回弹、头部及眼位误差阈值 1e-8，期望未复制正式 Python 公式。

`tools/capture_bounce_references.py` 通过 `git show` 提取并执行原生冻结提交 `4ecb85c8a087ca89fb99a3a2125c826801b53e1c` 的原模型和渲染器，生成 `tests/fixtures/bounce-native/` 中 32 张 PNG 及来源清单。八组真实点击场景 × 三档 DPR 1.0，加 320px 合成 DPR 1.5，覆盖峰值、恢复、第二阶段、眨眼与两种眨眼中连点、快速五次。日常测试只读取夹具，不导入原型或依赖历史 Git 对象。

## 自动化与范围

继续使用父规格已经确认的两处测试边界：应用点击/可控时间/手势/只读状态，以及 Qt 公开鼠标事件/大小/位置/最终图像/掩码。没有新增网格、缓存或私有方法测试边界。

- 32 个完整图像对照测试：误差不超过一个 RGBA 通道值，检查所有层共享锚点、缩放及遮挡。逐逻辑像素独立核对最终物理 alpha 与原生区域，窗口位置保持稳定。
- 应用级回弹检查：110ms 宽 110%/高 85%；220ms 恢复，目标头眼及阶段不变；连点重启及停止后不补完后续阶段。
- 应用及 Qt 手势回归：精确使用系统拖动阈值；拖动释放、拖回起点释放、合并移动事件、捕获中断和隐藏窗口均不改变头眼目标或重启现有回弹。轮廓变化期间手势仍可完成。
- 三个旧测试在头眼到位时原本比较整个状态永久不变；新增回弹后，保留原到位时刻的头眼断言，并等该次回弹至 220ms 再比较完整静止状态。

`native-capture.json` 的范围诊断按源头部相位 0..41、间隔 .25，共 165 点，与回弹两极值 `(1,1)`、`(1.1,.85)` 组成每档 330 帧，三档共 990 帧。此处仅为渲染范围诊断，将只读视图的回弹比例替换为两个极值；与应用/Qt 输入测试和真实可达轨迹明确分开。所有样本的非零 alpha 都在画布内：

| 高度 | 画布 | 采样 alpha 并集范围（左、上、右、下，含端点） |
| --- | --- | --- |
| 188 | 193×188 | 9,14,181,178 |
| 271 | 278×271 | 13,16,269,257 |
| 320 | 328×320 | 15,16,309,306 |

这不是连续空间的数学证明。独立极值不宣称全部是可达事件组合；同文件另记录三档各 15 张由真实 Qt 点击与应用时间到达的状态，包括四阶段峰值/恢复/停留和快速五次峰值/停留。

## 本轮真实 Windows 证据

`tools/verify_bounce_native.py --capture` 运行正式 `PetWindow`，使用隔离偏好。`native-capture.json` 中 45 个状态均通过可见处/透明角落的 `WindowFromPoint` 查询，相邻状态变化轮廓抽查最多 20 点。等待 Qt 计时器刷新、绘制和 layered-window 上传完成后再查原生命中，避免读取上一张已上传图像。PNG 是本轮正式窗口输出，`desktop-{light,dark,texture}-to-*-peak.png` 为真实桌面背景对照。已查看浅色第一阶段峰值和纹理第三阶段峰值，头颈与衣领同幅形变，未见独立领口分离。

`os-input-trace.jsonl` 是第一场真实 OS 鼠标会话，由 `computer-use` 输入产生：

- 透明画布内点击令下层 receiver 计数从 0 到 1，角色未推进；随后真实双击及两次单击到达 1、2、3、0，各次短暂回弹后恢复。
- 原生菜单切到持续模式后，动态头眼轮廓中拖动窗口从 `(650,300)` 到 `(750,350)`，释放不触发回弹；切回点击可收尾并从菜单退出。
- `os-session-result.json` 记录退出码 0、角色窗口关闭、下层点击数 1。

`capture-session/` 是单独补录的第二场会话。使用 GUI 线程 `GetCapture` 直接读取自动捕获；记录中三个捕获样本跨两个头部相位，拖动后窗口从 `(650,300)` 到 `(770,360)`，回弹比例保持 `(1,1)`，从菜单退出码 0。Qt 的 `mouseGrabber()` 只报告显式抓取，第一场日志中的 `qt_grabber_is_pet:false` 不代表 Windows 自动捕获丢失；第二场用原生句柄消除此歧义。

上述 OS 拖动在持续头眼运动中验证捕获；**回弹中**的拖动及手势中断由应用和 Qt 可控时间回归验证。没有把 Qt 合成事件写成 OS 输入，也没有把两场 OS 会话写成完整硬件验收。
