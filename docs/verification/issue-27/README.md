# #27 跨屏、混合 DPI 与屏幕变化

日期：2026-10-25。实现范围为正式源码 `PetWindow` 的屏幕选择、帧/命中同步及可见性恢复。父规格 #22 保持原样；安装包构建由 #28 承担。开始时已有规划、词表及历史工具/证据的未提交改动，均保留，未纳入本票提交。

## 行为与修复

沿用鼠标所在屏幕选择规则；逻辑桌面间隙比较到各屏矩形的距离。负坐标及工作区分别计算，不把虚拟桌面外包矩形当成可用区域。

本轮首先通过公开鼠标事件复现跨屏第一条 move 之后帧仍为旧 DPR 1.0、目标应为 1.5 的问题。现在先选择目标屏幕，再根据 Qt 当前窗口 DPR 重建物理图像与向外覆盖的逻辑命中区域，最后用新轮廓校正目标工作区。原生 DPR/屏幕通知仍延迟到下一轮事件检查，让 Qt 完成自身切换；夹具的同步结果不能证明 Windows 原生事件时序已在双屏验证。

第二条失败回归复现移除角色所在屏幕后仍使用已移除屏幕的情况。现在每次可见性检查先核对存活屏幕列表；当前屏幕失效时，按当前可见人物中心找最近屏幕并恢复。屏幕连接、几何和工作区信号及原生 DPR/屏幕通知均重新检查帧和可见区域。

轮廓与布局校正产生的位移进入现有手势补偿，防止按住期间工作区变化后，释放或下一条移动跳回旧原点。鼠标拖动的限位不计入该补偿；保留系统拖动阈值、捕获中断处理、拖动释放不推进阶段/回弹，以及 #26 的分方向贴边、离边解除、居中锚点和三档缩放规则。没有修改动作、素材、持久化字段或菜单。

## 自动化证据

测试只通过已确认的 Qt 公开鼠标/菜单/屏幕通知、屏幕查询夹具、窗口几何、最终图像与区域，以及应用时间/只读姿态观察行为；没有增加私有方法或缓存测试边界。

`tests/test_screens.py` 新增 13 项：

- 单次按住跨 100%→150%→200%→100% 屏幕，每条 move 后立即检查物理帧与每个逻辑像素的 alpha 覆盖；动作中拖入/拖出与释放保持手势，释放不额外启动动作。
- 移除负坐标屏后找回人物，使用剩余屏幕工作区与 DPR。
- 按住期间任务栏工作区或几何改变，仍保持右下贴边，释放不跳回原点或触发点击。
- 三档大小分别经过逻辑间隙/负坐标屏及 200% 屏幕，持续播放时边缘释放、四次时间采样、三档贴边缩放、离边居中稳定。
- 按住贴边时通知 DPR 变为 125%，立即检查新图像、完整覆盖的命中区域和释放位置。
- 屏幕连接通知找回越界人物，并检查后续工作区通知继续生效。

夹具布局：主屏 `(0,0,1920,1080)`，工作区 `(0,0,1920,1032)`；150% 屏 `(-2560,-240,1707,960)`，工作区 `(-2528,-200,1675,920)`；200% 屏 `(1920,-1440,1280,720)`，工作区 `(1920,-1400,1280,680)`。这些是自动化查询数据与合成 DPR 图像，不是物理显示器。

定向回归 **68 passed in 68.89s**；完整回归 **191 passed in 87.86s**，严格类型检查 **6 个源文件无错误**，原始结果见 [pytest.txt](pytest.txt)、[mypy.txt](mypy.txt)。完整回归继续覆盖旧动作、回弹、模式、设置、动态透明命中、四边四角和手势中断。

## 本轮原生环境与硬件限制

通过 `tools/verify_screens_native.py` 新采集环境及正式源码窗口启动观察，见 [environment.json](native-startup/environment.json)、[result.json](native-startup/result.json) 和 [trace.jsonl.gz](native-startup/trace.jsonl.gz)。Windows 11 build 26200、Python 3.14.4、PySide6/Qt 6.12.0、Qt windows 平台；实际仅 G24H1 一屏，1920×1080，工作区 1920×1032，DPR 1.0、96 DPI。

3 秒启动观察产生 64 个样本，均完整可见，最终帧 DPR 均为 1.0；窗口定时正常关闭，exit_code=0。这是本轮原生单屏启动记录，没有手动输入、桌面像素对照或多屏硬件操作。它不继承 #26 的真实 OS 操作结论，也不将 #20/#21 原型决策算作验收。

**真实双屏、混合 DPI、负坐标硬件、跨屏边缘释放、播放中切屏、任务栏调整和屏幕拔插全部待验。** 逐项条件、原因、证据要求及向 #28 安装版验收的交接见 [installer-handoff.md](installer-handoff.md)。#27 的对应硬件标准保持未勾选，不能描述为全部硬件场景通过。

## 重现

```powershell
$env:QT_QPA_PLATFORM='offscreen'
.\.venv\Scripts\python.exe -m pytest tests/test_screens.py -q --basetemp=.scratch/issue27-repeat
.\.venv\Scripts\python.exe -m mypy src
Remove-Item Env:QT_QPA_PLATFORM
.\.venv\Scripts\python.exe tools/verify_screens_native.py --output .scratch/issue27-native-repeat --seconds 3
```

硬件具备时改为 `--seconds 300`，手动按交接表操作。每轮使用新输出目录，工具拒绝覆盖已有 environment.json。日志仅记录观察，场景是否通过仍需人工结合 OS 输入及可复核证据判断。独立两轴审查见 [review.md](review.md)。
