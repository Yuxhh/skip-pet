# 文件桥协议 v1

适用 Issue #40，插件 0.2.0。参考 dsh-pet 固定提交 `34d810b1eadd98d00e7cb9b3b51428a45b5bf03e` 的按 PID 分文件、80ms 合批、1MiB 轮转和后台字节游标；身份、快照边界、独立健康、容量及保守清理由本项目补充。参考副本未修改。

## 身份与覆盖

所有文件必须有 `schema_version=1`、`owner=@sukuna-pet/dsh-bridge`、当前用户 home 规范化路径 SHA-256 的 `user_id`、实际宿主工作 profile 路径摘要 `profile_id`、`instance_id`、`pid`、Node `performance.timeOrigin` 的 `process_start_id`、每次装载 UUID `boot_id`、递增装载时间 `boot_started_at`、`host_version`、`plugin_version` 和能力集合。路径使用绝对规范路径，Windows 转小写；文件不传原路径、用户名或任务正文。宿主版本优先读取其包版本，无法读取时如实声明 `unknown`。

必要能力是 `observed-state`、`snapshot-boundary`、`contiguous-events`、`independent-health`。旧的最小桥 `schema=1` 没有这些字段，消费者拒绝接纳，须正常重开 Harness 加载新插件；不转换磁盘旧状态。观察范围仍为 `coverage=observed`、`scope=tracked-agents`，不代表完整宿主现态。未知范围、版本、能力、用户或身份不被当作空闲。

同一 PID 的进程启动身份及装载时间共同排序；新代原子替换旧代的消费状态，已退役或更旧的代际不再接纳。每路径保留至多 128 个退役身份，超限保守未知，消费者重开后重新建立连接。

## 文件与发布

- `dsh-{pid}.jsonl`：带完整身份、连续 `revision`、`emitted_at` 和事件白名单。业务状态包含 Agent、根轮次、当前轮次、已知性和状态；只导出必要 IDs/枚举。
- `dsh-{pid}.snapshot.json`：身份、`revision=N`、递增 `snapshot_seq`、`health_seq`、生命周期、覆盖声明及全部已跟踪状态。串行捕获边界后异步写同目录临时文件并 rename；替换失败不发布半份状态。
- `dsh-{pid}.health.json`：独立健康文件，每秒递增 `health_seq`，生命周期 `active/stopped`，以及最高丢失修订 `gap_revision`。状态/快照过大时仍可发布健康，不能以状态沉默推断宿主空闲。
- 大于 1MiB 的活动 JSONL 在下一批追加前轮转为 `.jsonl.1`，仅留一代；单文件包含最后一批时最多 2MiB。

插件写盘在一个串行异步任务中完成。一次只保留一个在写批次与一个有界待写队列；慢盘期间合并后续发布请求，捕获下一份最新现态，防止 Promise 队列无限积压。同 PID 重载时新写者等待旧写盘任务结束，旧代不能覆盖新文件。

## 消费与未知

后台消费者先建立日志 EOF 游标，再观察健康增长并取得同代快照。可信期间只应用 N+1 起的连续增量；重复边界不重放，旧轮结束不清当前轮，结束轮次不能被迟到状态复活。新快照可以推进现态边界，但不生成历史结束气泡。

缺号、乱序、异常身份、无法读取/解析的快照、超限、轮转或截断立即撤销该分区的文字与跳动事实，等待新发布且不低于最高已见修订的可信快照。轮转采取保守重新同步，未尝试拼接 `.1`；截断同时检查 inode、长度和游标前 64 字节，涵盖同尺寸原地重写。半行暂存而不解释为事件；新快照可恢复覆盖到的现态。一个分区未知不影响其他分区的可信任务，文案标记“已查清的”部分。

首次、重连、换代、消费者暂停后恢复均不回放旧结束提示。可信连续阶段的根轮结束只展示剩余有效期：`8 - (接收墙钟 - emitted_at)` 秒，再用单调时钟截止；过期、严重未来时间戳和重复结束不续期。其他运行/等待文字到期后仍保留。不同 Agent 的结束不代表根轮结束。

## 健康与资源

3 秒无有效健康增长确认失联；`stopped` 立即确认。确认即隐藏旧文字，仅此前已确认运行的根轮可到固定截止点再跳动最多 5 秒。重试或重复退出不改变截止点。健康仍在但状态有缺口时无此宽限。消费者先检查上次健康期限，再处理暂停期间的积压，防止恢复时回放结束。

限制：单记录 64KiB（含换行）、快照 8MiB、每次待应用读取 1MiB 或 1024 条、插件待写加在写事件合计 1MiB。溢出转未知，以新快照修复；插件使用 `gap_revision` 声明丢失边界。另保守限制消费者 64 个近期写者、每写者 4096 个 Agent/根身份、4096 个结束提示；插件限制 4096 个观察 Agent 和每 Agent 4096 个跟踪工具。超出观察能力时不声称完整覆盖。

每分钟最多检查 16 个超龄候选。仅匹配本用户、本协议、本插件，且健康与快照明确确认同代 `stopped` 时，清理超过 24 小时的对应文件；日志还逐条核验代际归属。活跃、崩溃但未明确退役、其他用户、未知协议、未知日志或链接文件均保留。删除前复核 inode/mtime/长度以避开替换，文件留存不延长状态有效期。清理不依赖 PID 单独探活，也不删除其他项目的数据。
