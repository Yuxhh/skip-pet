## Q2：插件写本机文件，桌宠后台读取

```text
Harness 内的桥接插件 → 本机 JSONL 事件文件 → 桌宠后台读取与归并 → 气泡及可选联动跳动
```

- 按宿主进程分区写文件；每次插件装载生成新 UUID，避免 PID 复用导致状态混淆。
- 沿用 80ms 事件合批、超过 1MB 轮转且保留一代备份的基线。
- 桌宠使用目录发现、按字节偏移增量读取与后台轮询；安装、修复及读盘不阻塞动画和鼠标处理。
- 本项目使用自己的插件标识和当前用户数据目录，与 dsh-pet 的桥文件分开归属。参考仓库是阅读资料，成品使用自身随包提供的实现。
- 数据只包含所需的身份、状态与一致性字段；按照既定边界去掉正文、问题/审批对象和凭据。

对应实现：上游 `integrations/dsh-pet-bridge/index.js` 的写入、轮转和启动 UUID；`pet/agent_link/__init__.py` 的 `ByteOffsetTailer`、`DirGlobTailer` 和 `DshMonitor`。

## Q3：插件随包提供，安装后自动维护旧链接

- 插件随桌宠分发，源码版和打包版分别定位到自身附带的目录。
- 首次启用接入时按参考流程说明安装范围并取得安装确认，后台执行安装；成功才保存已启用状态，失败报告实际结果。
- 参考 `install_bridge` 的本地包依赖和 bundle 维护，以及 Node/pnpm 发现与调用方式。安装预检必须识别日常桌面实际使用的 profile；创建一个与当前桌面无关的默认 profile 不算接入成功。
- 启动已启用的监测时，在后台检查已安装插件的路径。旧路径、失效路径或仍指向旧构建的本地依赖自动刷新到当前随包目录；自检只维护已安装插件，不代替首次安装，也尊重用户主动指定的 registry 版本依赖。
- 依赖补齐、坏路径修复和重试按参考实现核对，涉及的 profile、文件和依赖在预检中列清。配置备份与缺 pnpm 时的 JSON 卸载兜底也沿用参考机制，卸载失败保留诊断。
- 关闭接入或卸载时，按其他实例是否仍使用来决定是否移除共享插件；只删除本项目拥有的接入条目。部分 profile 安装成功而其他失败时，保留已成功项并如实报告，不宣称原子回滚或一键恢复。
- “接入启停”与“播放模式切换”分别处理。选择点击跳动或持续跳动只改变播放方式；仍需气泡监测时，不能因此自动卸载插件。

对应实现：上游 `bundled_plugin_dir`、`bridge_link_stale`、`refresh_stale_bridge_links`、`schedule_link_refresh_check`、`install_bridge`、`uninstall_bridge`、`AgentLinkManager.set_enabled`，以及 `pet/uninstall_cleanup.py`。

## 文件桥扩展：完整现态与最小协议

以下为落实既定需求的本项目设计，属于对参考文件桥的补充；不声称 dsh-pet 已实现这些扩展。

数据根目录选用当前用户的 `%LOCALAPPDATA%/sukuna-pet/bridge/dsh/`，插件标识为 `@sukuna-pet/dsh-bridge`。目录权限限当前用户；插件只观察状态，不发送消息、回答审批或修改会话运行。安装配置让插件与桌宠使用同一数据根目录，原宿主照常从日常快捷方式启动。

每个宿主进程使用 `dsh-{pid}.jsonl` 写增量事件，使用 `dsh-{pid}.snapshot.json` 原子发布最新完整现态与存活记录。快照先写同目录临时文件，完成后替换；替换失败保留旧文件，由存活机制识别失效，不把半份 JSON 当状态。轮转文件保留 `.1` 一代备份；轮转不等于任务结束。

| 信息 | 字段与约束 |
| --- | --- |
| 协议与能力 | `schema_version`、宿主版本、插件版本、支持能力；未知主版本或缺必要能力时不接纳状态 |
| 实例与代际 | 安装/profile 范围标识、PID、宿主进程启动身份、每次插件装载的新 `boot_id`；不能只凭 PID 归属 |
| 任务身份 | `conversation_id`、宿主稳定 `turn_id`，或经研究证明等价的轮次身份；缺失时不得仅凭聊天 ID 拼接历史 |
| 内部活动 | `agent_id`、所属根轮次、当前是否执行、已知性；子代理归入根轮次 |
| 待操作 | 请求标识、所属轮次/Agent、审批或回答、真实阻塞/已继续/已解除；只传状态枚举，不传请求内容 |
| 结束事实 | 对应轮次、完成/失败/中断；工具错误不自动等于整轮失败 |
| 一致性 | 同一 `boot_id` 内递增的 `revision`；快照包含边界 N 与覆盖范围，事件携带修订号 |
| 存活 | 单独递增的 `health_seq`、当前代际与生命周期（正常/退出）；业务无变化时仍递增 |

插件在同一宿主内串行归并观察到的状态：先订阅并缓冲变化，再安全枚举全部活动轮次和真实未决等待，建立边界 N。快照必须包含完整活动范围及明确未知部分；不能把“没有枚举到”直接写成无任务。重载时需要重新读取宿主当前事实，不能依赖插件重载前的内存。

每秒发布一次完整快照并递增 `health_seq`，状态变化仍走 80ms 合批事件。消费者先建立文件游标，再读快照，应用 N 及之后连续的增量；落在 N 之前的重复事件忽略。快照生成期间的事件由串行归并和修订号处理，不能漏掉订阅与枚举之间的变化。

发现缺号、轮转漏行、文件截断、读到不完整记录、错误代际或无法确认覆盖范围时，丢弃不可信的增量拼接，等待下一份可信完整快照。完整行之前的半行只暂存，不解析为事件。单条记录上限 64KiB、完整快照上限 8MiB、未应用增量缓冲上限 1MiB 或 1024 条；超过任一界限即转未知并重新同步，不无限积压。插件待写事件队列也限 1MiB，溢出时标记缺口并以新完整现态恢复。

首次启动、重连与插件换代均从未知开始。消费者观察到当前代际存活计数继续增长，并取得该代际可信完整快照后，才把现态送给聚合器；新代际原子替换对应旧现态。上一轮迟到事件、上一代记录和缓存运行状态不能复活任务。首次或恢复快照不回放历史结束提示；当前同步阶段收到的有效结束变化才触发 8 秒气泡展示，缓冲超过展示期限的结束提示不再展示。

## 存活、断线、有效期与恢复

- 每秒快照中的 `health_seq` 是插件健康信号；接收方用自己的单调时钟记录其增长。业务事件沉默、文件 EOF、端口或进程单独存在均不作为插件健康证明。
- 连续 3 秒没有观察到有效健康计数增长时，确认该观察通道失联；看到当前代际明确退出记录时立即确认。3 秒是检测窗口，之后才开始既定的最多 5 秒跳动宽限，不能把两者混称为从最后事件起 5 秒。
- 确认失联立即隐藏该端旧文字；只把之前已确认运行的状态用于固定截止点的 5 秒宽限。失败重试不重置截止点，单独旧运行事件也不能续期。其他可信任务仍在运行时继续跳动。
- 健康通道仍活着但状态序列有缺口，属于未知并等待快照，不套用失联的跳动宽限。未知不得当作空闲、完成或失败。
- 当前可信活动状态由同代际新快照和连续事件刷新；失联运行缓存最多 5 秒，结束提示最多 8 秒。进程重启不恢复旧活动缓存，文件留存期限不延长任务事实的有效期。
- 每代 JSONL 保留当前与一代轮转文件，快照只保留最新一份。确认对应写者代际已经退出后，超过 24 小时的遗留文件可清理；无法证明写者归属或存活状态时保留，由正常轮转限制活动日志增长。未知协议文件不自动清理。卸载仅处理本项目拥有且无其他实例使用的文件和配置。
- 升级失配或刷新失败的恢复次序：核对当前包及实际 desktop profile → 重开两端并重新同步 → 重跑参考的安装/链接修复 → 仍失败则记录未通过门槛或移除自己的接入。保留配置差异与备份，避免整份旧配置覆盖其后的用户修改；不能靠重置全部第三方插件或另启宿主掩盖故障。

健康周期、容量边界与快照原子替换须通过后面的负载和原生文件系统检查。失败时停止发布并修订工程规格；不会自动改变已定的状态语义、5 秒宽限或 8 秒提示时长。
