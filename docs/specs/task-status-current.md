## 已确认的产品行为

### 任务与三种模式

- 一个宿主聊天中的一轮用户请求是一个任务，子代理归入该轮，不额外计数。同聊天下一轮是新任务，旧轮结束不能清除新轮，也不能影响其他聊天的任务。
- 同轮内部仍有助手执行工作就属于运行任务；即使同时待批准或待回答，仍按一个运行任务计数，同时保留待操作提示。内部没有助手继续执行，且有真实待操作事项时，才属于等待任务。
- 保留点击跳动、持续跳动、任务联动三种模式。任务联动模式下任一已确认任务运行则持续跳动；只剩等待时不触发自动跳动，没有运行任务时自然收尾，空闲仍可手动点击推进阶段。
- 监测接入与播放模式分开。切换点击跳动或持续跳动不应关闭气泡监测或卸载插件。原有眼动、点击回弹、拖动、缩放与贴边行为继续保留。

### 气泡文字、时长与外观

- 采用 A「一句话气泡」，使用短促、傲慢、带嘲讽的宿傩口吻；不输出服务式客套话。具体人设以[原始口吻要求](https://github.com/xyd-0811/skip-pet/issues/36#issuecomment-6398066382)为准，角色语气不能推断任务成功或未知进度。
- 运行、等待期间常驻，状态改变后更新。完成、失败、中断保持区别，结束提示展示 8 秒；到期只移除结束部分，仍有运行或等待时继续显示对应信息。
- 并发信息合成在同一气泡中；结束提示不能覆盖仍待用户操作的信息。同轮运行且待操作不重复计为两个任务。
- **气泡随文字自动缩放**：短句缩小，长句在宽度上限内扩展；达到可用宽度后自然换行、增加高度，文字变短后重新收缩。保留适当内边距，不使用固定大小空框。
- **透明圆角**：气泡底板和边框采用平滑圆角，圆角外透明，不露出矩形窗口底色。使用独立且输入透明的气泡窗口，不新增点击操作，不拦截角色和下方应用的输入。
- 优先位于角色头顶，上方放不下时移至下方，必要时侧移，限制在角色所在屏幕的工作区内。文字尺寸变化、拖动、角色缩放和切屏后重新定位。

| 状态 | 已确认文案方向 |
| --- | --- |
| 运行 | 哼，还在办。等着。 |
| 等待批准 | 小鬼，等你点头。 |
| 等待回答 | 话说清楚，小鬼。等你回答。 |
| 完成 | 哼，办完了。 |
| 失败 | 啧，失败了。回去看。 |

数字、等待类型及台词组合依据已确认事实变化；这张表不表示当前代码已经覆盖所有等待类型和逐字文案。

### 未知、断线与恢复

- 未查清的任务不显示文字，不显示“状态未知”“正在同步”或替代闲聊；未知不计为空闲、完成或失败。部分已知只显示已知部分，并明确计数仅代表已查清部分。
- 刚启动尚未确认有任务运行时不自动跳动；其他可信任务仍运行时继续联动。
- 业务无新事件不等于断线。目标健康机制为每秒独立发布，连续 3 秒无有效健康增长确认失联，明确退出则立即确认。
- 确认失联立即隐藏该端旧文字；只有先前已确认运行的状态可再用于最多 5 秒跳动宽限，从确认断线时起算，不能因重试续期。旧的 10 秒规则已被替代。
- 重连、插件换代后从未知开始，确认当前代际健康增长并查清最新状态后再恢复；旧轮、旧代和历史结束提示不能复活任务或回放。状态序列缺口与真正失联分别处理，目标细节见传递和维护规格。

### 接入与范围

- DeepSeek 先行，保留后续 Codex 和双端支持目标。宿主仍从日常桌面入口启动，不用另起 CLI 或 app-server 代替原实例接入。
- Q2/Q3 已选定 dsh-pet 方案：宿主内精简插件写本机文件，桌宠后台读取；插件随包提供，首次安装确认、后续旧链接自动维护、备份和移除按既定机制实现。参考基线及必要差异见[源码参考规则](../agents/dsh-pet-reference.md)。
- 只传必要身份与状态，不传聊天正文、命令、问题、答复或凭据；观察不改变宿主的审批、回答或任务执行。
- 不增加任务列表、点击定位聊天或任务控制。接入能力说明（包括“Codex 暂不支持”的菜单或气泡）已明确延至下一版本，当前不补做这一说明功能。
