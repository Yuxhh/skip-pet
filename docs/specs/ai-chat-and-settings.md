## 产品范围与界面

首版包括独立文字聊天窗口、流式回复、新建/切换/删除会话、本地完整记录、停止、手动重试、用户自备 DeepSeek API Key，以及简化桌宠设置。

采用已确认的 Sukuna AI 黑红原型：宿傩标记、神龛线稿、侧栏、字体层级及背景密度。空会话将欢迎区与约 110px 输入框紧凑居中；多行输入自增高，聊天时输入框置底，消息区滚动；顶部仅保留会话与模型信息，提高辅助文字对比度。首版无附件入口。

右键菜单新增“AI 对话”“桌宠设置”，保留模式/大小快捷项。重复打开激活同一对应窗口，关闭聊天窗口不退出桌宠。正式窗口采用项目现有 PySide6 技术；HTML 是确认资产，不能直接当成正式产品。

| 设置分组 | 内容 |
| --- | --- |
| 桌宠 | 三种跳动模式与小/中/大；沿用 188/271/320px 档位 |
| 任务联动 | 已有宿主接入状态、启停与维护入口 |
| AI 对话 | Key 保存/取消/清除、Key 是否已保存状态、主动连接测试、仅本次运行降级提示 |
| 关于 | 产品名、实际版本与必要开源署名 |

原型中的 deepseek-chat 为示例，正式实现必须按行为决议使用 deepseek-flash 并关闭思考。原型示例回复、模拟连接和置顶示意不构成功能验收。正式界面应补足删除确认、重试、未完成标记与密钥保存/取消/清除。

不加入联网搜索、语音、附件、长期记忆、自动总结、云同步、多角色、多服务商、模型选择或用户编辑人设。AI 回复不进入任务状态气泡，不触发任务联动跳动。

## 请求与角色

沿用研究快照的官方接口 https://api.deepseek.com/chat/completions，Bearer 鉴权，固定 deepseek-flash，显式关闭思考。开发接入时重新核对官方契约；若模型或参数变化，报告具体差异，不静默改模型。使用者只需配置 Key。

新会话保存创建时作者提示词正文、补充要求的可恢复快照与版本；旧会话重启后继续使用旧快照，新会话使用最新作者版本。不只保存可能无法恢复的版本号。

正文遵循作者原文；补充要求为“嘴上狂傲，内容有用”“复杂问题可展开但言简意赅”“短动作偶尔出现，以台词为主”。不加入上游友善默认人设、场景扮演、时间或记忆规则。本机记录允许时间元数据，但不自动注入模型。

本地保留完整记录。请求历史沿用固定上游 trim_history：从最近向前取，至多 40 条、24,000 字符，单条过长历史可只传尾部，再恢复时间顺序。此限制针对历史，system 与本轮用户输入按上游结构另外加入。较早记录不能被裁掉；不自动总结，不静默重发容量错误请求。

网络请求在后台执行；SSE 解析覆盖分块事件、UTF-8 拆分、正文、结束标记及 finish_reason。EOF 不等于完整成功。思考字段不展示、不回传。首字等待期间显示正在生成并可停止；GUI 不冻结。

## 会话与异常

| 操作或异常 | 必须行为 |
| --- | --- |
| 新建、切换、关闭聊天窗口 | 停止当前生成；若已收到正文，将部分回复保存到原会话并标记未完成；回调绑定原会话及请求 ID，迟到事件不得污染新状态 |
| 手动停止 | 保留已接收内容，标记未完成；不承诺服务端立即停止计算或计费 |
| 删除 | 先确认，生成中先停止；只删除选中的本地记录，旧排队写盘不得复活它 |
| 普通追问 | 可把未完成回复作为上下文 |
| 重试 | 对原问题发起新请求并替换部分回复；原问题不重复入历史，不把被替换回复放入重试上下文；可能再次消耗额度 |
| 缺失或无效 Key | 提示配置或更新，引导至 AI 对话设置；修复后手动发送 |
| 余额不足、限流、服务繁忙 | 分别提示并手动重试；不自动重发 |
| 断网、超时、流中断 | 保留已收到正文并标记未完成，显示中断原因 |
| 记录损坏 | 时间戳备份并报错，不静默覆盖；备份失败仍保留原文件 |
| 写盘失败 | 保留可见内容并标记尚未保存；关窗提供重试、取消关闭、确认关闭，并提示可能丢失未写入内容 |

区分界面停止与后台线程退出。旧请求完成不得覆盖新请求，窗口销毁不得导致运行中的 QThread 被销毁。网络必须有界超时，数值及取消清理策略在实现时记录和验证；上游 60 秒网络超时不能冒充整轮硬截止。

## 设置、凭据与兼容

桌宠模式、大小和任务联动偏好立即生效并保存。快捷菜单与设置窗口使用同一状态来源及操作入口，复用现有模式、动画和桥接维护行为。

设置中的 Key 状态只显示当前 Key 是否已安全保存；主动连接测试的结果作为单次反馈，不保留为“当前在线”状态。Key 已保存不代表接口此刻可达。

Key 修改暂存到“保存”，取消放弃，空白不改旧值。“清除密钥”立即删除当前运行内存与安全存储中的 Key，并清除尚未保存的输入框草稿，不等保存；删除失败必须如实提示，不能显示已清除却又恢复旧 Key。这不会在服务商处撤销 Key。

使用 Windows 当前用户的安全凭据存储，可采用 Credential Manager 适配器；参考上游 SecretStore 的隔离和失败处理。安全存储不可用时只留运行内存，提示重启需重输，绝不写明文配置。Key 不进日志、聊天记录、源码、错误回显或 Issue。

连接测试只在主动点击时发送一次简短真实生成请求，预先说明可能消耗 API 用量；保存不自动测试。建议用表单待测 Key，为空则用现有 Key；测试成功不隐式保存，不写聊天历史，不代表流式或语气验收。测试同样关闭思考。

请求启动时取得凭据快照；后续保存/清除控制后续请求，不能承诺撤回已经发出的服务商请求。清除后释放应用保留的凭据引用。

建议在应用自己的 QStandardPaths 数据目录按会话保存版本化记录，精确字段与目录由实现确定。至少保存稳定 ID、角色/正文/消息状态、请求关联、时间与作者版本快照。使用同目录临时文件及原子替换，串行有序写盘；失败不破坏最后成功版本。重启恢复记录及未完成标记，异常退出的生成中回复不能冒充完成。

兼容现有 mode.json 的 mode、size、dsh_bridge，新增配置不丢弃既有未知字段。记录与凭据隔离；不导入或改写 D:/dsh-pet 个人数据。未知记录版本保留原文件并提示，不覆盖成空记录。
