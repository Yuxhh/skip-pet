# V5 原生接入实验（可丢弃，贴边方案已确认）

决策票：[已确认跳动采用怎样的原生渲染与桌面交互方案](https://github.com/xyd-0811/skip-pet/issues/21)。本目录仅验证接入路线，不是正式版本。

从仓库根目录运行：

```powershell
.venv/Scripts/python.exe .scratch/sukuna-pet/prototypes/native-v5/preview.py
```

独立的 Windows 透明角色和控制窗同时出现。可直接点击、拖动角色；控制窗可切换三档大小、四个停留姿态、最强回弹帧、持续跳动和点击模式。新增四个“贴边”按钮方便检查各方向，也可直接拖到边缘。模式、大小和位置只在内存中保存；退出隔离预览即可结束。

素材来自不可变提交 `32c9f985d4467c1527b09c34f6868a3ccd3f85b4`，保存在 `frozen/`，哈希见 `evidence/observations.json`。不依赖相邻历史原型或运行中的网页。

`preview.py` 使用 Qt QImage/QPainter 渲染分层角色，使用最终帧的 alpha 生成原生窗口 QRegion。QJSEngine 直接运行冻结的动作模型；为兼容 Qt JS 解析器，运行时仅把对象展开浅复制改写成等价的 `Object.assign`，原始文件不改写。没有 WebView、HTML 页面或浏览器参与原生绘制。

用户在本轮明确选择：持续跳动沿用 V5 演示，动作完成后约停 450ms，再自动进行下一阶段并触发 Q 弹。已移除无间隔循环候选入口；切回点击只停止自动调度，当前动作仍收尾并停留。

用户同时纠正：拖动必须可以让人物紧贴屏幕边缘。初版按透明画布限位的方案已撤回；当前按最终帧的可见轮廓限位，透明区域可在屏幕外。贴边时保留所贴的边，动作中随轮廓变化调整窗口位置，人物仍完整可见。居中播放时不引入窗口位移。

窗口高度严格为 188、271、320 个 Qt 逻辑像素，320 为最大档；完整运动画布统一缩放到所选高度，因此不会因加画布余量把窗口变大。控制窗显示实际尺寸和贴边状态。

运行事实验证：

```powershell
.venv/Scripts/python.exe .scratch/sukuna-pet/prototypes/native-v5/observe_native.py
```

该脚本会短暂打开第二组独立实验窗口，产生三档姿态图、Windows 原生命中记录、拖动/连点/眨眼/自动播放观察、DPR 栅格样本及 330 帧运动范围采样。`evidence/native-contact-sheet.png` 是 Qt 渲染输出拼图；原生命中证据由 Windows `WindowFromPoint` 读取，Qt 手势实验与实际 OS 输入的边界单独记录。

本轮用户对修订后的贴边表现明确回复「符合，可以采用」。最初反馈的具体偏差是「拖动应该能紧贴屏幕边缘」，当前方案按该反馈修订。

本机仅一块 100% 缩放显示器。1.25/1.5/2 DPR 样本是绘制实验，不能替代实际跨屏和混合 DPI 拖动验收；该项仍待真实硬件验证。没有把运行成功作为视觉认可。
