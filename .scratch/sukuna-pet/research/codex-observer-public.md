# Codex 任务状态协议与桌宠提示的接入门槛

本报告仅包含公开官方协议和通用研究结论，不包含本机安装信息或发行物分析。

## 本轮功能范围

桌宠通过上方文字气泡提示任务状态；菜单增加任务联动模式，任一任务运行时自动跳动。已有点击跳动与持续跳动模式保留。不提供任务列表、任务导航或 agent 控制。

这些是产品目标，并不意味着状态来源已经完成连接或验证。

## 研究结论

**Codex App Server 提供状态协议原料，但公开协议存在，不能证明独立桌宠可以观察用户照常打开的桌面实例。** 本轮未获得足以宣称此项兼容已经通过的证据；方案仍需先证明“连接到原桌面实例并获得完整状态”这一门槛。

实际阅读的第一方来源为 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)。本报告不把官方协议说明写成产品接入已验收，也不从有限检索推断所有接入入口绝对不存在。

## 官方协议可提供的原料

官方文档列出 `thread/loaded/list`、`thread/read`、`thread/status/changed`、`turn/completed` 和 `serverRequest/resolved`。装载列表与执行状态分别表达；状态通知的示例包含 `active` 及 `waitingOnApproval` 标志，因此不能把每一个活动线程都当成正在执行。以上均为协议能力，仍须验证实际宿主的覆盖范围与状态转换。[来源：App Server](https://learn.chatgpt.com/docs/app-server)

文档描述了先启动监听服务、再让另一终端连接的用法，也说明订阅与线程生命周期。此类受控服务示例不自动证明其与已经运行的桌面宿主共享实例；把另启服务的状态显示到气泡中，仍可能遗漏原有聊天。此处是根据文档做出的覆盖范围推论。[来源：App Server](https://learn.chatgpt.com/docs/app-server)

文档将 WebSocket 传输标为实验性且不受支持，并描述认证和连接初始化。即使后续找到合适端点，也需要明确兼容范围与访问权限，不应通过任意开放无认证监听来替代受支持的连接方式。[来源：App Server](https://learn.chatgpt.com/docs/app-server)

## 接入前还需要证明什么

1. **实例身份与覆盖**：连接的是照常启动的桌面宿主，能看到原本存在的任务，而不是仅看到新建受控服务的任务。
2. **初始和恢复状态**：桌宠晚启动或重连后，能够取得最新完整状态；快照与订阅之间不会漏掉变化。
3. **运行和等待**：能区分运行、审批等待、用户回答等待和恢复；一项等待不会覆盖另一项仍在执行的任务。
4. **结束与故障**：能区分完成、中断、失败、未知与宿主连接中断，不把缺失状态默认为空闲。
5. **可靠存活信号**：有明确关闭或约定探活结果；事件流没有新消息不等于断线。断线后的既定宽限从确认断线起算。

这些是待验证的工程门槛，不是本报告已经执行通过的测试。

## 推荐的下一步

先取得确切、合法且有版本依据的桌面观察入口，再制作可关闭的最小只读探针。探针只收集任务标识、运行/等待状态、连接代际与快照序号，不发送任务、不回答审批、不读取聊天正文。先证明状态来源，再接正式气泡与动画。

探针应验证桌宠先后启动、并发任务、等待与恢复、完成与失败、确认断线和重连；随后检查任务联动模式与现有两种模式的切换。若只能取得部分状态，必须明确呈现能力缺失，不能以“已完成”或“空闲”掩盖未知。

当前没有足够依据要求用户修改某个桌面配置键或安装某个已验证桥接包。若后续仍缺支持入口，需在决策票中明确选择等待接口或经用户理解后调整兼容范围。本研究完成仅表示取得有界结论，不表示接入方案已经可直接实施。
